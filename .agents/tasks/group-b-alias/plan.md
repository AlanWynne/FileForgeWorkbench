## Design decisions made during exploration (grounded in the code read)

- D1. The real on-disk alias row (`crates/ff-desktop/src/shell/user_aliases.rs::UserAliasRowToml`) is the CR-CH-072 shape: `surface`, `canonical`, `environment` (`#[serde(skip)]`, from the `<ENV>.toml` file name), `command_template` (`#[serde(default, skip_serializing_if="String::is_empty")`). There is NO `localisation_key`. Req 7's Description is ADDED as an optional `#[serde(default, skip_serializing_if="String::is_empty")] description: String` (empty string, not `Option`, to match the existing `command_template` convention and keep round-trip byte-stable for files without it). The working-copy `AliasRowEdit` (`crates/ff-desktop/src/alias_editor_panel/state.rs`) gains a matching `description: String` field.
- D2. The shared component lives at `crates/ff-desktop/src/shell/ispf_table_editor/` (mod.rs re-export + `state.rs`, `line_commands.rs`, `sort.rs`, `render.rs`) per design "Where the component lives". It is a generic helper over a host trait `IspfTableHost`, NOT a new crate. The Alias panel (`crate::alias_editor_panel`) implements `IspfTableHost` and calls the shared render.
- D3. Line-command engine reuse: the shared `line_commands.rs` classifies Act letters by calling `ff_line_commands::LineCommandParser::parse(act, backing_idx as u64)` + `ff_line_commands::command::classify(&kind)`. It maps `LineCommandKind::{Insert,Delete}` -> immediate (descending-index), `Copy`/`After`/`Before` -> source/target pairing, per design. No `ff-line-commands` public-API change. The apply pass operates on a generic `Vec<Row>` through the host's `blank_row()` / `clone_row()`, so it is pure and unit-testable without egui.
- D4. Alias Line_Command_Set = I, D, C, SORT (Req 7.4). M (Move) NOT enabled. R MAY remain as a single-row-copy alias (Req 7.6) but C is the primary; keep R mapping to the clone-after behaviour to avoid regressing the existing `repeat_duplicates_row_values_into_new_row` test, OR migrate that test to C. Decision: keep R as clone-after in the shared immediate set for the Alias host (cheap, preserves behaviour), and ADD C/A/B pairing. This retires `shell/alias_editor_line_commands.rs::apply_pending_line_commands` in favour of the shared pass.
- D5. Sort ordering (Req 7.5 / 7.5a): canonical key = `surface.to_uppercase()` ascending, stable, with `canonical.to_uppercase()` as tie-breaker; scoped per environment. Since the store is already one `<ENV>.toml` file per environment, `write_override_rows` already groups by environment -- sort each env's `Vec<UserAliasRowToml>` by the key just before serialise. The SAME key function powers the manual `SORT` command (over the working `Vec<AliasRowEdit>`, also grouped/stable) so manual and auto ordering are identical. A single `fn alias_sort_key(surface, canonical) -> (String, String)` is the shared source of truth.
- D6. Resolver UNCHANGED: `AliasTable::canonical_verb` in `shell/environment.rs` stays a linear `eq_ignore_ascii_case` scan over `Vec<AliasEntry>`. No map/binary-search. Confirm by NOT editing that file.
- D7. Save convention, focus contract, dispatch, navigation, descriptor, `pending_action` swap: all UNCHANGED. The Alias editor already routes SAVE/END/CANCEL/REFRESH through the CR-CH-071 `editable_context` seam (`shell/alias_editor.rs::alias_editor_persist/discard/reload`) and reports `InteriorFocus` via `render_workspace_context` (dispatch arm in `shell/render_body.rs`, `TabKind::AliasEditor`). The redesign moves presentation + line-command behaviour onto the shared component without touching these seams.
- D8. First interior control stays the FILTER CE dropdown (Req 7.8, 5.23). The shared render must capture and report it as `first`/`last` exactly as `alias_editor_panel/render.rs::render_filter_row` does today, so the existing `full_shell_alias_editor_first_tab_focuses_first_interior` test keeps passing.
- D9. Column order becomes Act, CE, Command(canonical), Alias(surface), Parameters(command_template), Description (Req 7.2). The ScreenProvider table (`shell/screen_providers_tables.rs::alias_table`) and its test (`shell/tests_editor_snapshot_tables.rs`) gain the Description column, in that order (Req 7.9).
