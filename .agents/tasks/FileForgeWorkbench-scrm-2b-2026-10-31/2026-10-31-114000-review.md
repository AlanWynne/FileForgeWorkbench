# Three-flavor composite SNAPSHOT clipboard (window screenshot + Unicode Markdown + CF_HTML)

Bare `SNAPSHOT` is reworked from a single text-rasterised PNG into a three-flavor Windows clipboard transaction: a real window screenshot (CF_DIB + CF_DIBV5), Unicode box-drawn Markdown text (CF_UNICODETEXT), and a CF_HTML composite that embeds the PNG as a base64 `<img>` above the box-drawn text in a monospaced `<pre>`, so a Word paste takes both picture and text. Because egui 0.33's window screenshot is asynchronous, the command phase stashes the two model-derived text flavors and raises a request; the frame loop issues `ViewportCommand::Screenshot` and assembles the payload when the `Event::Screenshot` arrives. The format picker is retired and ANSI never reaches the clipboard. `ff-screen-model` stays egui-free; the only egui-touching new code is the `screenshot` adapter in `ff-desktop`.

Watch for: nothing blocking. The live "picture pastes into Word" proof is owner-manual (a headless host cannot assert the Win32 clipboard contract or a live window grab); the CF_HTML byte offsets, the three-flavor transaction, the egui-free boundary, the dispatch seam, ASCII-only source, and the sub-400-line rule are all verified below. The owner's full `cargo gate` on this worktree was CLEAN (4652/4652).

**Verdict**: APPROVED

## High-level view

The async two-phase flow is the central design choice and it is implemented cleanly. The command phase resolves the active `ScreenProvider` while `&self` is valid, renders both text flavors there (so the frame loop never touches `ff_screen_model`), stashes a `PendingSnapshot { text, pre_text }`, and sets a one-shot request flag. The frame loop sends the screenshot viewport command, then on a later frame drains `Event::Screenshot` and assembles the payload. This mirrors the existing `pending_menu_option` / `pending_tab_actions` deferred-action pattern and is non-blocking with no spin-wait.

The CF_HTML builder computes the four header byte offsets correctly using a fixed-width (10-digit zero-padded) placeholder header so the header length is stable across the two passes. StartHTML indexes the document start, StartFragment lands just after the `<!--StartFragment-->` marker, EndFragment just before `<!--EndFragment-->`, and EndHTML at the payload end; the round-trip test parses all four back and asserts each. Base64 and HTML-escaping are in-module, so no new dependency.

The picture flavors reuse the existing verbatim DIB layout (`raster_to_dib` strips the 14-byte file header; `raster_to_dib_v5` rebuilds a 124-byte V5 header over the same BGR pixels) and are now fed the real window RGBA via `from_window_capture` rather than a model raster. All three flavors (plus a best-effort registered PNG) are published inside one `clipboard-win` open with `raw::set_without_clear`, so they are offered simultaneously.

The egui boundary holds: `ff-screen-model/Cargo.toml` has no egui dependency, and `color_image_to_raster` is the sole new adapter, living in `ff-desktop`. The dispatch seam is untouched: `commands_ladder_b.rs` still routes `SNAPSHOT` through `handle_snapshot` via the single front door, with no bespoke intercept.

### Two-phase async flow and the egui-free boundary

The split is the right shape for egui 0.33's asynchronous window screenshot. `snapshot_composite_to_clipboard` resolves `active_screen_capture()` (handling `ScreenCapture::OptOut` with the existing not-capturable error), renders `text` as `SnapshotFormat::Markdown` and `pre_text` as `PlainText` with `RenderOptions::default()` (which is `unicode_box: true`), stashes both in `PendingSnapshot`, sets `screenshot_requested`, and clears `open_error`. It no longer builds a payload or touches the clipboard. Rendering both text flavors here, in the command phase where the `ScreenProvider` seam lives, is what keeps `update.rs` and the assembly helper from ever calling into `ff_screen_model` — the frame loop only moves egui types and calls the prebuilt adapters. `ff-screen-model/Cargo.toml` confirms no egui dependency, and `screenshot::color_image_to_raster` is the only new egui-touching code.

The frame loop drains the screenshot in the deferred-action cluster: if `screenshot_requested`, clear it and send `ViewportCommand::Screenshot(UserData::default())` leaving `pending` in place; then, while `pending.is_some()`, scan `ctx.input(|i| i.raw.events)` for `Event::Screenshot`, clone the `Arc<ColorImage>` out of the closure, and on arrival `take()` the pending and call `place_snapshot_composite`. Non-blocking, no spin-wait.

### CF_HTML header offsets

The two-pass construction is correct. A fixed-width placeholder header (`{ph}` = `"0000000000"`) fixes `header_len`, then the real offsets are computed against that length and written with `{...:010}` so the header byte length is identical between passes (asserted by a `debug_assert_eq!`). `start_html = header_len` indexes the document prefix `<html>...`; `start_fragment = start_html + doc_prefix.len()` lands immediately after `<!--StartFragment-->`; `end_fragment = start_fragment + body.len()` lands immediately before `<!--EndFragment-->`; `end_html = end_fragment + doc_suffix.len()` equals the payload length. All four are byte counts (ASCII header, `.len()` is bytes, CF_HTML is UTF-8). The `cf_html_header_offsets_index_the_markers` test parses each integer back and asserts the indexed bytes, and `base64_padding_is_correct` covers each residue class.

### Picture flavors from the real window RGBA

`from_window_capture(image, text)` PNG-encodes the captured raster directly and stores it with `html: None`, with no model rasterisation — this is the fix for the earlier bug where the "picture" was a raster of the text render. The DIB/DIBV5 builders are reused unchanged, so the pixel layout is shared across BMP, CF_DIB, and CF_DIBV5 (the V5/DIB pixel-equality test proves it). `OsClipboard::place` opens `clipboard-win` once and publishes CF_UNICODETEXT, CF_DIB, CF_DIBV5, a registered PNG, and (when `payload.html` is `Some`) the registered `"HTML Format"`, all with `raw::set_without_clear` so they coexist in one transaction. `from_model` is retained as the test-only, model-rasterising constructor behind `#[cfg_attr(not(test), allow(dead_code))]`, which resolves the dead-code warning without deleting the tested path.

### Dispatch seam, ASCII, and line budget

`commands_ladder_b.rs` still matches `SNAPSHOT` / `SNAPSHOT ` and calls `handle_snapshot(arg)` through the single front door; no second dispatcher or intercept was added, and the explicit `SNAPSHOT <FORMAT>` file/PDF paths are untouched (ANSI reachable only as a file, never a clipboard flavor; no picker). A scan of the touched source for non-ASCII found only a pre-existing box-glyph comment separator in `update.rs` line 322 — present in the base and outside this change's added lines; all added code is ASCII and the only box glyphs are built from `'\u{250C}'`-style char constants in tests. Non-test line counts are within budget: `clipboard_backend.rs` test module starts at line 388, `update.rs` at 387, `commands_snapshot.rs` is 295 with no test module, and `state_groups.rs` is 259.
